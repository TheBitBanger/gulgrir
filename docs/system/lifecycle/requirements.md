# Lifecycle requirements

| ID    | Need                                                                                                                                                                       | Why                                                                                                                    |
| ----- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------- |
| LCY-1 | A user needs every item in exactly one stage, from wishlist through acquired and in progress to done.                                                                       | To see at a glance where each thing stands. Wishlist and acquired come mostly from integration statuses (IMP-4).      |
| LCY-2 | A user needs to mark something finished but still ongoing, like a game whose story is done while multiplayer continues, or an MMO that adds questlines.                     | It can still be picked without counting as unfinished, and replays of the finite part stay visible.                   |
| LCY-3 | A user needs to make progress on an item and return it to the backlog without finishing it.                                                                                | So long items can rotate with others.                                                                                  |
| LCY-4 | A user needs a history of when, and how many times, each item was completed or revisited.                                                                                   | It drives revisit reminders and selection, and it's their own record.                                                 |
| LCY-5 | A user needs to restart a completed item, like a reread or replay, without losing its history.                                                                            | Favorites come around again.                                                                                           |
| LCY-6 | A user needs to mark something abandoned, and the system needs to tell abandoned apart from finished.                                                                      | If a tag and a stage both claim it, the system can't tell what really happened.                                        |
